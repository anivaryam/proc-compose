# proc-compose baseline for LLM-agent local development

## 1. What already exists, and where does the product stop?

### Takeaway

proc-compose already provides most agent-facing lifecycle primitives; “add JSON,” “support worktrees,” and “keep a stack running” would reinvent existing capabilities. Its stated positioning is a native local-process orchestrator for development/small deployments, explicitly without containers, images, networks, or volumes. [README.md:7–19](../../../README.md#L7-L19)

**Scope/method:** original read-only research on 2026-10-19. `git rev-parse HEAD` confirmed **main@7a9e93d3361278e72d72672f6253773c96e73ad7**; initial status showed no tracked changes, only existing untracked `reports/` and `research_notes/`. Documentation, implementations, selected test assertions and two prior records were inspected. No services, suites, builds, installations or application/data operations ran. Test citations mean **assertions inspected, not tests passed**. This note was subsequently corrected in the approved documentation slice following the [adversarial review](../../reports/Adversarial%20review%20of%20agent%20research.md); code remains unchanged, no runtime evidence was added, and the [canonical pilot](../../reports/Agent%20workflow%20opportunities%20and%20validation.md#canonical-pilot) supersedes earlier experiment variants.

## 2. Which gaps are real, and which increments are plausibly small?

### Takeaway

The public retained-check gap is real, but exposing an existing function is not a complete implementation. Smaller candidates concern documentation accuracy and machine-readable mutation contracts; their implementation scope is narrower, but workload benefit remains unmeasured. [ipc.go:253–284](../../../internal/ipc/ipc.go#L253-L284), [main.go:670–784](../../../cmd/proc-compose/main.go#L670-L784)

### Cited Findings

- **Retained managed checks: absent publicly.** The actual daemon dispatcher handles only restart/reload/shutdown; unknown actions fail. `verify` refuses an occupied session. Thus retained stacks exist, but a public “run an owned check against this existing stack” operation does not. [runner.go:607–684](../../../internal/runner/runner.go#L607-L684), [verify.go:81–95](../../../cmd/proc-compose/verify.go#L81-L95)
- **`RunCheck` does own ordinary check cleanup.** Cancellation terminates its group; the shared executor also tears down descendants after natural leader exit. A deadline test asserts termination before returning without handoff. However, blocked reap can return `HandedOff`, leaving terminal stack sealing responsible. Other survivor/escape evidence is recorded globally rather than exposed as an independent per-check cleanup verdict. [check.go:80–158](../../../internal/runner/check.go#L80-L158), [lifecycle.go:674–687](../../../internal/runner/lifecycle.go#L674-L687), [lifecycle.go:782–814](../../../internal/runner/lifecycle.go#L782-L814), [runner_test.go:4138–4157](../../../internal/runner/runner_test.go#L4138-L4157), [runner_test.go:4635–4707](../../../internal/runner/runner_test.go#L4635-L4707)
- **A warm verifier requires orchestration.** Required-service monitoring and final cleanup interpretation belong to `verify`, not `RunCheck`; check names cannot repeat and remain registered. A long check cannot simply block the serial dispatcher: IPC waits only 30 seconds for its acknowledgment. [operation.go:473–497](../../../internal/verify/operation.go#L473-L497), [operation.go:647–672](../../../internal/verify/operation.go#L647-L672), [operation.go:816–864](../../../internal/verify/operation.go#L816-L864), [check.go:112–122](../../../internal/runner/check.go#L112-L122), [server.go:227–257](../../../internal/ipc/server.go#L227-L257)
- **Mutation ergonomics have a narrower gap.** Internal status/message/generation acknowledgments already exist; public restart/reload use human output, and the command wire shape has no expected-run precondition. Failed commands may emit stderr only. [ipc.go:253–284](../../../internal/ipc/ipc.go#L253-L284), [main.go:695–781](../../../cmd/proc-compose/main.go#L695-L781), [GUIDE.md:110–111](../../../internal/agentguide/GUIDE.md#L110-L111)
- **Do not promise universal cleanup safety.** Crash recovery holds the session lease and rechecks replacements; PID/start-time defenses have legacy/unreadable-time fallbacks. Documentation explicitly warns that macOS daemon-PID reuse can signal an unrelated process. Escaped groups are outside crash records; readable legacy `stop --force` can exit 0 with an unverified-process warning. [helpers.go:563–640](../../../cmd/proc-compose/helpers.go#L563-L640), [daemon.go:195–231](../../../internal/daemon/daemon.go#L195-L231), [Stop a running daemon](../../../docs/cli.md#stop-a-running-daemon)
- **Readiness is not identity attestation.** Linux/Windows attribute probe sockets; macOS cannot. `verify` rejects attributed cross-live-session answers by default; Windows refusal covers only another session's leased port, and macOS never refuses. Outside-session/unattributable answers can pass. Check connections and loaded code remain unobserved. [Verified runs](../../../docs/verify.md), [Environment reports](../../../docs/verify.md#environment-reports)

### Inferences

**Bounded opportunities, not approved features:**

1. **Documentation correction applied:** the [inspected CLI text](https://github.com/anivaryam/proc-compose/blob/7a9e93d3361278e72d72672f6253773c96e73ad7/docs/cli.md#L80-L107) wrongly described direct `$TMPDIR` fallback and loss of `logs` access with a custom log file. [Current documentation](../../../docs/cli.md#daemon-file-paths) now describes per-user cache before temp and the independent journal. No runtime behavior changed. [paths.go:31–49](../../../internal/paths/paths.go#L31-L49), [logs.go:48–73](../../../cmd/proc-compose/logs.go#L48-L73), [main.go:315–319](../../../cmd/proc-compose/main.go#L315-L319)
2. **Optional structured mutations/run pinning:** extend existing acknowledgments, preserving generation waiting, partial reload and shutdown-verdict delivery. An expected-run guard could reject stale discovery-to-mutation intent; it would not authenticate ownership. No wrong-run incident was established here. [ipc.go:209–250](../../../internal/ipc/ipc.go#L209-L250), [runner.go:655–683](../../../internal/runner/runner.go#L655-L683)
3. **Application integration before new attestation:** reuse the existing environment-report example, which already covers build/fixture/worker identity and concurrent state interference. Its synthetic pilot is not evidence of general workload compatibility. [example README:8–16](../../../examples/environment-report/README.md#L8-L16), [example README:42–74](../../../examples/environment-report/README.md#L42-L74), [example README:93–97](../../../examples/environment-report/README.md#L93-L97)
4. **Conditional retained checks:** investigate only if existing retained sessions plus bounded host checks lack necessary ownership/evidence. Admission/concurrent mutation policy, per-check cleanup proof, repeat identity, environment handling and bounded history are prerequisites—not optional polish. [check.go:80–158](../../../internal/runner/check.go#L80-L158), [operation.go:466–497](../../../internal/verify/operation.go#L466-L497)

**Reuse/rejected reinvention:** reuse CLI, leases, journals, acknowledgment and verifier layers; reject a parallel runner/log reader/report format. Also reject `RunCheck` alone as a complete retained verifier: passing command exit is not a combined environment/service/cleanup verdict. [operation.go:466–497](../../../internal/verify/operation.go#L466-L497), [operation.go:798–864](../../../internal/verify/operation.go#L798-L864)

### Gaps

- Retained per-check cleanup after incomplete reap is unresolved; safe admission during restart/reload and bounded repeated history need a specified contract. Need/demand, implementation cost and risk frequency are unknown.

## 3. What timing evidence exists, and what experiment could disprove a proposal?

### Takeaway

The bounded available sample supports no speedup estimate or performance-led feature ranking. Existing retained orchestration must be the comparator, not an assumption that every check requires cold startup. [prior coverage note:110–139](../Local%20development%20agent%20opportunities/local%20workflow%20and%20coverage.md#L110-L139)

### Cited Findings

- Inspected **one prior synthesis and its workflow/coverage note**, not original application logs or personal session histories. They transcribe four historical browser invocation totals: **47.2, 35.1, 42.2, 25.7 seconds**, with different failures/journeys; three later passing repetitions after a harness correction: **43.4, 44.2, 43.3 seconds**. These describe one application workflow, not matched edit/check trials. [prior synthesis:17–23](../../reports/Local%20development%20agent%20opportunities.md#L17-L23), [prior note:120–128](../Local%20development%20agent%20opportunities/local%20workflow%20and%20coverage.md#L120-L128)
- The note records approximately **1.03–1.07 seconds** per app start-to-available and a reporter-estimated **10.3-second** startup decomposition. Launch overlap/raw spans were unavailable; summed concurrent service time is not wall-clock savings. [prior note:123–128](../Local%20development%20agent%20opportunities/local%20workflow%20and%20coverage.md#L123-L128)
- That earlier researcher found zero receipts in two specified runtime/cache roots. This search was **not repeated today**; no current receipt sample was inspected. Runtime receipts can disappear at logout/reboot. [prior note:118](../Local%20development%20agent%20opportunities/local%20workflow%20and%20coverage.md#L118), [Verified runs](../../../docs/verify.md)

### Inferences

**Pilot specification:** use only the study's [canonical pilot](../../reports/Agent%20workflow%20opportunities%20and%20validation.md#canonical-pilot), requiring separate approval. It compares the actual working CLI/Playwright baseline (preserving legitimate reuse) with existing retained proc-compose plus a recipe, across three actual edits. This replaces this note's earlier fresh-`verify` comparator. Evidence must count eligible contract exposures, independently observe safety boundaries, and separate complete wall-clock time from cumulative concurrency. No pilot has run; follow the canonical specification for exact controls and decisions rather than treating this summary as a second design.

### Gaps

- Missing: paired workloads, raw dependency/launch spans, phase receipts, agent interaction latency, reset compatibility, present-day demand and accepted benefit threshold. No unmeasured time saving should appear in the final study.
