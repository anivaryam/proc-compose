For deliberate warm development, use the same explicit config/session for retained `up`, `status`, targeted generation-aware restart, a separately bounded host check, and an explicit final `stop` whose exit status matters. Do not present it as equivalent safety merely because the check returns 0. [Verifier wrapper](../../../internal/verify/operation.go#L466-L497), [runner-owned check contract](../../../internal/runner/check.go#L16-L47).

#### C1 — daemon-managed checks against an already-running retained session

- **Current coverage / concrete gap:** `Runner.RunCheck` already executes direct argv in an owned process group with cancellation, bounded output, and cleanup handoff. But the public daemon command protocol and actual dispatcher support only `restart`, `reload`, and `shutdown`; a check action does not exist. `verify` explicitly refuses an occupied session. This is a real interface/semantic gap, not absence of a command-execution engine. [RunCheck](../../../internal/runner/check.go#L16-L47), [execution/admission](../../../internal/runner/check.go#L80-L158), [protocol](../../../internal/ipc/ipc.go#L268-L284), [dispatcher](../../../internal/runner/runner.go#L611-L670), [verify admission](../../../cmd/proc-compose/verify.go#L81-L95).
- **Workload relevance:** repeated same-test invocations with fresh startup are recorded, so retained checks are a plausible option for investigation. The records do not establish that these invocations may safely retain app services through their DB resets, that the existing launcher supports external endpoints, or that a bounded B0 host check is insufficient. [Gate command/reset evidence](file:///mnt/c/Users/U%20S%20E%20R%20-PC/Documents/workflow-runs/pre-pr-local-gates/GATE-REPORT.md#L204-L217), [later audit conditions](file:///mnt/c/Users/U%20S%20E%20R%20-PC/Documents/workflow-runs/resident-id-card-photo-qr/IMPLEMENTATION-AUDIT-REPORT-2.md#L181-L197).
- **Implementation boundary, not “just a CLI switch”:** reuse the existing runner, IPC acknowledgment path, verifier verdict/evidence machinery, and journals if justified later. First resolve retained-session ownership, per-check cancellation/cleanup verdicts without ending the stack, required-service monitoring, repeated-check naming/history/retention, and admission/concurrency. `RunCheck` rejects repeated names and retains their state in its registry; using unique names is not itself a history-retention policy. Required-service monitoring currently lives outside it. [Registry/admission](../../../internal/runner/check.go#L89-L122), [duplicate-name test](../../../internal/runner/runner_test.go#L4046-L4065), [monitor wrapper](../../../internal/verify/operation.go#L473-L494).

A test asserts that the unresolved check is ultimately reported through `Unresolved`/`ShutdownResult`; the verifier then derives its cleanup verdict from those stack results. This cannot be advertised as a complete standalone per-check cleanup receipt while retaining services. [Handoff contract](../../../internal/runner/check.go#L80-L88), [blocked-reap test](../../../internal/runner/runner_test.go#L4635-L4707), [verifier cleanup verdict](../../../internal/verify/operation.go#L816-L864).

Existing tests pin only parts of this, and were not executed here. If B0 retained checks already satisfy the actual requirement, or lifecycle startup is immaterial, there is no demonstrated C1 case. [Required-service tests](../../../internal/verify/verify_test.go#L644-L708), [active-check shutdown test](../../../internal/runner/runner_test.go#L4535-L4632), [handoff test](../../../internal/runner/runner_test.go#L4635-L4707).
