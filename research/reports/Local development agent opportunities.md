## Existing retained orchestration narrows the real increments

`agent-guide`, `config check/plan/schema` and `sessions --json` already support discovery/static preflight; a plan is not a run or database safety audit ([GUIDE.md:137–153](../../internal/agentguide/GUIDE.md#L137-L153)).

| **B0: retained development/context** | `up --silent --wait-ready --json`, `status`, generation-aware `restart --wait-ready`, separately bounded host checks and final `stop`; bounded journals/cursors and `why` already exist. | Host checks do not automatically gain verifier-owned check containment/combined verdicts. **Exposing `RunCheck` alone is insufficient.** Independent cancellation normally tears down its check group; incomplete reap can return `HandedOff` for terminal whole-stack sealing. That is not standalone cleanup proof while retaining services; inspected tests assert this distinction. Existing journalling is reusable, but required-service monitoring, environment handling, per-check journal attribution and bounded repeat history need orchestration; names currently cannot repeat and unique names alone do not bound accumulated state ([check.go:80–158](../../internal/runner/check.go#L80-L158), [handoff test:4635–4707](../../internal/runner/runner_test.go#L4635-L4707), [verifier:435–497](../../internal/verify/operation.go#L435-L497)). Long checks must not block serial command dispatch or rely on its **30-second acknowledgment** window ([runner.go:607–684](../../internal/runner/runner.go#L607-L684), [server.go:227–265](../../internal/ipc/server.go#L227-L265)).

C2 must preserve existing instance/resource leases, PID/start-time defenses and crash-path replacement rechecks; legacy/platform fallbacks exist. Optional run pinning prevents stale intent, **not unauthorized access** ([session.go:34–71](../../internal/session/session.go#L34-L71), [daemon.go:195–231](../../internal/daemon/daemon.go#L195-L231), [helpers.go:563–590](../../cmd/proc-compose/helpers.go#L563-L590)). `stop` itself excludes descendants that escape recorded groups ([main.go:461–486](../../cmd/proc-compose/main.go#L461-L486)).

## A compatibility pilot must beat retained B0 before code

**Strongest counterevidence:** the local gate already reported cleanup and later green checks; existing retained B0 avoids unnecessary cold starts. Docker Compose also documents detached lifetime, running/healthy waits, changed-container reconciliation and selected check exit-code propagation for containerized workloads—not arbitrary native processes ([Compose up](https://docs.docker.com/reference/cli/docker/compose/up/)). A reported Windows Job Object wrapper helped MCP descendants, although it did not prove the Bash/Vite path fixed ([workaround](https://github.com/anthropics/claude-code/issues/62659#issuecomment-4567917620)). Neither another generic API/dashboard nor universal attestation is selected. Reject a new check engine, log reader, lease system or report format; reject `RunCheck`-only reuse as an end-to-end verifier.

**One next action:** seek approval for a compatibility/demand pilot using existing capabilities. First confirm the existing browser launcher can consume externally managed endpoints and retain services safely through its guarded fixture policy. Stop if it launches a competing stack, needs stopped services for every reset, or changes cold-start acceptance; do not build a parallel harness to manufacture compatibility. Unknowns include installed harness/version behavior, present demand, reset validity, critical-path costs and retained per-check cleanup feasibility.

If compatible and explicitly authorized, select one representative task with **three sequential matched edit/check iterations per B0 arm**: fresh `verify` versus retained `up/status`, only-needed generation-aware restart and bounded host checks. Keep assertions, source/build state and fixture policy equivalent. Record phase wall-clock spans, including retained initial startup/final stop, resets/restarts, command counts, manual agent interventions and actual dependency overlap. Include bounded cancellation/descendant cleanup and handoff observations with an unrelated-process negative control; verify endpoint/build/fixture evidence through real application paths. Do not sum concurrent service durations into elapsed time.

**Proposed policy, requiring agreement:** zero false identity/cleanup passes or unrelated-process interference; stop on unsafe/unverified cleanup. A C1 proposal requires a reproducible retained-B0 ownership/evidence deficit in at least two of three iterations after correct existing-tool use. Agree any speed materiality threshold beforehand. Retention-only speed gains credit B0, not C1. If B0 suffices, lifecycle cost is immaterial, or reuse is incompatible, **build nothing**. These are proposed gates, not measured results. Service launches, representative edits, fixture resets, fault seeding and cleanup require separate scoped permission; none occurred today.
